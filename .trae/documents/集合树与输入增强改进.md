# 集合树与输入增强改进（Wails 桌面客户端）

## Context（背景）

用户针对 Wails 桌面客户端（Vue3/TS 前端，`frontend/src`）提出 2 项新增 + 2 项调整：

1. **新增**：输入变量（`{{var}}`）时自动提示候选，按 Tab 直接录入。
2. **新增**：JSON 请求体输入时，`{ }`、`[ ]`、`"` 自动配对补全（光标居中）。
3. **调整**：集合树根标题取消加粗。
4. **调整**：集合树的顶部工具条（展开/收起、新建分组、新建请求、导入 cURL）以及根行上的重新载入/关闭收起，统一移入集合标题行的 "···" 下拉。

已与用户确认的决策：
- 顶部工具条**整体移除**，操作收进每个集合标题行的 "···" 下拉，作用于**该集合（工作目录）**。
- 变量自动提示候选 = **当前集合·所处环境的所有变量 + 4 个内置动态变量**（`$uuid`/`$timestamp`/`$isoTimestamp`/`$randomInt`）。
- JSON 配对覆盖 `{ }`、`[ ]`、`"` 三种（不包含单引号、圆括号）。

## 改动 1：VarInput 变量自动提示 + Tab 录入

**文件**：`frontend/src/components/VarInput.vue`、`frontend/src/stores/collection.ts`、`frontend/src/components/RequestBar.vue`、`frontend/src/i18n/locales/{zh-CN,en-US}.ts`

核心：`VarInput` 是一个「透明文字 input + 高亮层」组件，原生 input 带 `selectionStart/End`。在其上叠加自动提示层。

- `VarInput` 新增可选 prop `suggestions?: string[]`（变量名候选；**不传则不启用提示**，保持现有调用兼容）。
- 监听 input 的 `input`/`keydown`：读取当前 `selectionStart`，向前解析出最近一个未闭合的 `{{` 内已输入的前缀（`/\{\{([A-Za-z_$][A-Za-z0-9_]*)$/` 之类）；若在 open 花括号内则过滤 `suggestions` 弹出候选浮层（复用现有 `.tip` 层同风格）。
- 按 `Tab`/`Enter` 选中高亮项：把当前 `{{前缀…}}` 片段替换/补全为 `{{name}}`，并把光标放到 `}}` 前。`Esc` 关闭候选。方向键切换高亮。
- 追加候选（若使用方未传全）：组件内部把 4 个内置变量（`$uuid`/`$timestamp`/`$isoTimestamp`/`$randomInt`）固定并入候选。
- 提供 `data-testid="var.suggest"`（候选浮层）与候选行 `var.suggest.item`，遵循 `模块.子域.元素` 命名。
- 新增 i18n key（如 `varSelectHint`/`varBuiltin` 标题），`zh-CN.ts` 与 `en-US.ts` 必须一一对应。

**候选数据来源**：`collection.ts` 增加 getter `currentEnvVarNames(): string[]` —— 取 `activeRoot` 对应集合当前 `currentEnv` 的 `Env.vars[].name` 列表（`Env` 结构见 `types.ts:211`，带 `vars: EnvVar[]`）。`RequestBar.vue` 中 2 处 `VarInput`（URL / 请求头处，`RequestBar.vue:183-204` 附近）把该 getter 结果 + 内置变量作为 `suggestions` 传入。

## 改动 2：JSON 请求体自动配对补全

**文件**：`frontend/src/components/JsonBodyEditor.vue`

`JsonBodyEditor` 是「textarea + 高亮层」（`JsonBodyEditor.vue:39-56`）。在 `<textarea class="ta">` 上加 `@keydown` 处理配对（读 `selectionStart/End`，操作 `props.modelValue` 手改后 `emit('update:modelValue')`）。

规则：
- 输入开放符 `{` / `[` / `"`：
  - 若存在选中文本 → 用「开放符 + 选中 + 闭合符」包裹选中；
  - 否则在光标处插入「开放符 + 闭合符」并把光标保持在两者中间。
- 输入闭合符 `}` / `]` / `"`：若文字紧跟其后已是同闭合符（`typed over` 场景），则只右移光标，不重复自补。
- 可选：退格时光标前后是 `配对` 对则一起删除（保持与自动补全对称，作为可选小增强）。
- 复用现有高亮机制，改动仅局限在事件处理层，不影响高亮/scroll 同步。

## 改动 3：集合标题取消加粗

**文件**：`frontend/src/components/Sidebar.vue`

`Sidebar.vue:1275-1279` 的 `.row.root > .coll-name` 去掉 `font-weight: 700`（改为不声明或 `font-weight: 500`）。保留字号（15px / root-active 16px）与强调色（`--app-accent-dark`/`--app-info-tint` 底色），层级区分依旧靠字号+底色。

## 改动 4：顶部工具条迁入集合标题的 "···" 下拉

**文件**：`frontend/src/components/Sidebar.vue`

- 删除 `.head` 顶栏里的 4 个按钮（展开/收起 `toggleAll`、新建分组 `startAdd`、新建请求下拉 `newMenu`、导入 cURL），保留必要结构或整块移除（`.search` 搜索行保留）。
- 集合根行（`Sidebar.vue:760-807`）右侧加一个 `···` NDropdown（`data-testid="tree.root.menu"`），下拉选项（复用现有 `tree.*` i18n key，均有定义）：
  - 展开/收起（`toggleAll`，标题按 `allCollapsed` 切换）
  - 新建分组（`startAdd(root,'')`）
  - 新建请求 · HTTP（`emit('new-request', '')`）
  - 新建请求 · gRPC（`emit('new-grpc-request', '')`）
  - 导入 cURL（`emit('import-curl', '')`）
  - 重新载入（`emit('reload-root', root)`）
  - 关闭工作目录（`emit('close-root', root)` + 现有二次确认逻辑）
- 每个动作触发前先 `await ensureActive(root)`（`Sidebar.vue:303`，内部 `tabs.switchRoot`），保证写操作落到**被点击的那个集合/工作目录**。
- "···" 按钮需 `@click.stop` / 阻止冒泡，避免触发根行 `activate`（根行 `@click="emit('activate', row.root)"`）与折叠逻辑。
- 原根行右侧 `reload`/`close` 两个 `.act` 按钮（`Sidebar.vue:794-806`）移到下拉内。
- `folderMenu`/`newMenu` 里新建请求的相关项，若需在目录级保留则不变（仅整理根级入口）。

## 验证

1. 类型检查：`cd frontend && npm run build`（或 `npx vue-tsc --noEmit`）确认无 TS 错误；`npm run i18n:check`（若存在该脚本）校验中英 key 一致。
2. 手动（`wails dev`）核对：
   - 变量：在 URL/请求头输入 `{{` 出现候选，Tab 录入 `{{name}}`，内置 `$uuid` 可补。
   - JSON：请求体输入 `{`、`[`、`"` 光标居中，闭合符已同时出现；重复输入闭合符不重叠。
   - 集合树：标题不再加粗；点 "···" 可新建分组/请求、导入 cURL、展开/收起、重新载入、关闭；操作生效于被点击的集合。
3. 若正好集合为空、无根行时，确认无残留顶栏占位导致的空态问题。
