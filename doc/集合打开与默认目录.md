# 集合打开与会话模型

> 更新：2026-11-05。对应改动：集合初始化闸门（`9308d60`）、默认集合（`c605159`）。
> 涉及：`internal/collection/collection.go`、`internal/app/app.go`、`frontend/src/App.vue`。

## 一、集合的身份标记

一个目录算不算「本项目的集合」，只看一件事：有没有 **`opencollection.yml`**（`collection.go:126`）。

该文件同时承载：集合 UID、名称、gRPC 默认配置、集合级 defaults（公共请求头/认证）。

## 二、打开流程（三岔口）

`collection.Open(dir)` 按目录状态分三种处理：

| 目录状态 | 行为 |
|---|---|
| 有 `opencollection.yml` | 直接载入（历史根恢复走的也是这条） |
| 不存在 / 空目录 | 返回 `ErrNeedsInit`，同样要用户确认（避免选错目录后留下无主文件） |
| **有内容但无清单** | 返回 `ErrNeedsInit`，**不写盘、不载入**，等用户确认 |

「有内容」的判定排除版本控制与同步副产物：`.git`、`.gitignore`、`.sync.json`、`.DS_Store`。

用户确认后走 `collection.Init(dir)` → `App.InitCollection(dir)`：先补 `opencollection.yml`，再按正常流程打开。

确认框是 Naive UI 的居中 `n-modal`（`data-testid="welcome.needsInitDialog"`），不再用 `window.confirm` ——
后者在 Wails 的 WebKit 里位置不受控，会贴在窗口顶部。

「新建集合」入口（侧栏 +「新建」）传 `create=true`，直接 `InitCollection`，不会重复询问。
命令行 `-dir` 与 devserver 同理（视为用户明确指定）。

> **提示文案必须说明**：初始化后目录里既有的 `.yml` 会被识别为本项目的接口。用户点「取消」时什么都不做 —— 不进内存、不进最近列表、不落盘。

## 三、没有任何集合时的行为

旧行为：启动后停在欢迎页，必须先选一个目录才能进入主界面。

新行为：`App.EnsureDefaultCollection()` ——

1. 已经有活动根 → 原样返回该集合（幂等）；
2. 没有活动根 → 在**应用配置目录**下创建并打开 `default-collection`。

配置目录 = `config.Dir()`，即 `~/.config/api-doc-client`（Linux，受 `XDG_CONFIG_HOME` / `API_DOC_CONFIG_DIR` 影响）、`%AppData%\api-doc-client`（Windows）。

前端启动顺序（`App.vue`）：

```
settingsReady → restoreRoots()（恢复历史根）
             → 若 coll.ready 仍为 false → api.ensureDefaultCollection() → coll.loadRoots()
```

结果：**启动即进主界面**，用户直接新建请求，保存位置就是 `default-collection`。

为什么不放「文档目录」：默认集合是应用自己的兜底存储，不该污染用户的文档/桌面；放配置目录也便于随配置一起备份或清理。

## 四、与其它机制的关系

| 机制 | 交互 |
|---|---|
| 历史根恢复（`restoreRoots`） | 优先；恢复成功就不用默认集合，否则每次启动都会跳回 default |
| 最近目录列表 | 取消初始化时**不写入**，避免下次又被静默提示 |
| 同步绑定（`.sync.json`） | 与集合目录绑定；默认集合同样可以绑定服务端项目 |
| `-dir <目录>` 命令行 | 直接打开指定目录（同样经过初始化闸门） |

## 五、验证方式

后端（devserver，无需 GUI）：

```bash
# 有内容无清单 → 报未初始化
curl -X POST $DEV/api/App/OpenCollection -d '["/tmp/col-dirty"]'
# → {"error":"目录尚未初始化","ok":false}

# 空目录 → 直接打开
curl -X POST $DEV/api/App/OpenCollection -d '["/tmp/col-empty"]'

# 确认初始化 → 生成清单并载入
curl -X POST $DEV/api/App/InitCollection -d '["/tmp/col-dirty"]'

# 无根 → 创建默认集合
curl -X POST $DEV/api/App/CloseCollection -d '["<某根>"]'
curl -X POST $DEV/api/App/EnsureDefaultCollection -d '[]'
# → data.dir = <配置目录>/default-collection
```

已实测通过（2026-11-05）：脏目录拒绝、空目录直开、初始化后生成 `opencollection.yml`、关闭全部根后创建 `default-collection`。

## 六、已知遗留

- 桌面端二进制在无头环境（Xvfb + WebKit）启动后 `exit=1`，未能截图确认主界面。后端接口层与前端类型检查均通过，**需要在真实桌面环境复验一次启动流程**。
- 「有内容但只有子目录、没有文件」也会被判定为需要初始化 —— 这是有意为之（避免把别人的项目目录误吞）。
