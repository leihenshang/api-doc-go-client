## 2026.9.28（补充）

- [x] naive-ui 在 Web 端与客户端显示不一致
  - 先排除版本因素：两端 **naive-ui 均为 2.45.3、vue 均为 3.5.43**，完全一致。真实差异有三层：
    1. **主题覆盖**：Web 的 `n-config-provider` 传了 `themeOverrides`（主色、`borderRadius 4px/3px`、`Card.paddingMedium`、`DataTable.thColor/thFontWeight`）与 `:date-locale`；客户端此前只传 `:locale` → 走 naive-ui 默认（**圆角 3px/2px**、卡片与表头样式不同、中文下日期为英文）。
    2. **基础排版**：Web `body` 为 `14px` 且字体栈含 `BlinkMacSystemFont`/`Hiragino Sans GB`；客户端此前是 `13px` + 更短字体栈 + `-webkit-font-smoothing`。
    3. **渲染与字体环境**：Wails Linux 链接 **WebKitGTK 4.0**（`libwebkit2gtk-4.0.so.37`），Web 端跑 Chromium → 字体度量、原生控件、CSS 支持度不同；且本机 `fc-list :lang=zh` 仅有 1 个字体（Droid Sans Fallback），`fc-match "Microsoft YaHei"/"PingFang SC"` 回退到无中文字形的 DejaVu Sans。
  - 已对齐（第 1、2 层）：客户端 `App.vue` 逐字搬入 Web 的 `themeOverrides` 并补 `:date-locale`；`styles/base.css` 对齐字体栈与基准字号 14px、去掉 `-webkit-font-smoothing`；通用令牌（`--app-bg/--app-border/--app-text/--app-muted`）改为 Web 同值，工作台专有令牌（`--app-sidebar/--app-send` 等）保留。
  - 实测：`body` 字号 14px、字体栈含 BlinkMacSystemFont；naive-ui 按钮/输入框/下拉圆角 **4px**；`--app-bg=#f5f6f8`、`--app-border=#ebedf0`、`--app-text=#1f2329`。
  - **第 3 层无法靠配置消除**（WebKitGTK ≠ Chromium），目标定为「组件主题与排版尽量一致，不追求像素级相同」。
- [x] 集合区域字体「非常粗、生硬」，希望有不依赖系统字体的方案
  - 原因两条：① 侧栏标题「集合」是 `font-weight: 700` + `letter-spacing: 1px`、分组名是 `600`，而系统可用中文字体只有 Droid Sans Fallback（**单一字面、无粗体**），浏览器只能用「合成粗体」把笔画硬撑粗；② 次像素渲染在 WebKitGTK 上边缘发毛。
  - 采用**随包内置字体**方案（不再依赖系统是否装中文字体）：`@fontsource-variable/noto-sans-sc`（Noto Sans SC **可变字体**，100–900 真字重，SIL OFL 可分发），字体栈把它放第一位，系统字体仅兜底。
  - 同时 `body { font-synthesis: none }` 禁止合成粗体/斜体；恢复 `-webkit-font-smoothing: antialiased`（灰度渲染更干净）；侧栏「集合」去掉 `letter-spacing` 并把字重收到 600、分组名 600 → 500。
  - 实测：`document.fonts.check('14px "Noto Sans SC Variable"', '用户管理订单中心')` 为 `true`（字形覆盖）；拉丁字宽 145 vs 系统 156.56（说明确实在用内置字体）；`font-synthesis` 计算值为 `none`。
  - 代价：字体按 unicode-range 拆成 **98 个 woff2 子集（合计 4.6 MB）**，`frontend/dist` 从 2.8 MB 涨到 7.5 MB（按需加载，只下载页面用到的子集；Wails 内嵌进二进制后 +约 4.6 MB）。
  - 可选优化：若在意包体，可只保留常用字子集（约 1.5–2 MB），代价是生僻字回退系统字体；或改为依赖系统 `fonts-noto-cjk`（需用户环境配合）。
