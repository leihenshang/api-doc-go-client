# 客户端问题记录

记录客户端的缺陷、根因与处理；**新的写在最上面**，只留「现象 → 根因 → 改法/验证」，过程性叙述不再展开。
功能清单见《客户端功能规划与完成情况.md》；设计与方案见同目录其它文档与 `.doc/`。

## 2026.10.7（集合树：根级连接线 + 集合字号层级 + 点名字折展）

- [x] **环境切换下拉「失效」**（缺陷）：`Toolbar.vue` 里写了 `const { name, envs, currentEnv } = props` —— **解构 props 会丢掉响应性**，此后环境列表怎么变，下拉拿到的都是首次渲染那份快照。实测：在环境管理里新建 `env-2`（store 里已经有了、弹窗左侧也列出来了），工具条下拉仍然只有 `dev`，根本选不到 → 用户看到的就是「切不过去」。改法：删掉解构，模板一律用 `props.envs` / `props.currentEnv` / `props.name`（顺带修掉集合名 `name` 同样的陈旧问题）。验证：`env-manager.spec.ts` 断言新建后下拉立刻包含该环境、选中后当前环境按根持久化为它。
- [x] **保存环境变量后弹窗不关**（体验）：`EnvManager.save()` 只弹了 toast，弹窗留在原地 —— 明明保存成功，却要用户自己再点一次「取消」才关。改法：保存成功后 `close()`（结果由 toast 说明）。
- [x] **清理废弃文案键**：`toolbar.openDir`（「打开其他集合…」）全仓库无引用，与新的下拉项「打开集合」语义几乎重合、容易误改，已从两份语言包移除。
- [x] **只能点小箭头才能折展分组**（体验）：分组行的名字是普通 `<span>`，点它没有任何反应；箭头的命中区只有 16px，想折展必须精准点到它。改法：行点击对**分组**改为折叠/展开（请求行仍是打开页签），并在行内控件（箭头 / 「+」下拉 / 操作按钮 / 重命名输入框）上放行，避免点「+」建子项时顺带折展一次。
- [x] **箭头折展「折了又展」等于没反应**（连带修掉的真 bug）：行点击加上分组折展后，点箭头会先由箭头自己的 handler 折一次 —— 而折展会**换掉箭头里的图标节点**，同一个 click 继续冒泡到行时 `ev.target` 已经脱离 DOM，行里那句 `closest('.caret')` 判不出来 → 又折一次，净效果为零。改法：箭头加 `.stop`（与根行箭头一致），不再冒泡到行。教训：**依据 `ev.target` 做「是不是控件」的判定，在「控件自身会改动 DOM」的 handler 之后并不可靠**（用 `ev.currentTarget`/坐标或直接 `.stop` 更稳）。
- [x] **集合根行与它的子级之间没有连接线**（缺陷）：连接线只画 `depth > 0`，而直接挂在集合根下的分组/请求是深度 0 —— 于是「集合 → 顶层分组」这一节是断的（进到分组里面才有线）。改法：深度 0 也画（它那一列正好是根行展开图标的圆心），根行自己再补一段从**行中线**落到行底的接出线（`.gl.root-down`），两段接上就是一条完整分支；根行收起 / 集合为空时不画，避免悬空竖线；行内「新建分组」输入行同样接在这一列上。
- [x] **根级「新建分组」会渲染出多个输入框**（发现）：那个输入行挂成了 `v-if / v-else-if` 链里的一支，条件只看 `adding.parent === ''`（没限定是哪一行），于是根下每个非根行都能匹配、各渲染一个输入框（`@demo` 用例不在门禁里，一直没暴露）。改法：把输入行走进「根行」分支里（一个根只有一个根行），顺带让它与子行同缩进、同连接线。
- [x] **集合目录的字号其实没生效**（缺陷）：`.coll-name` 写的是 14px，但 `.row > .rname`（同为两个类、位置在前）也用同权重命中根行的名字并给 12.5px —— 实际生效的是 12.5px，集合层级和子项一样大。改法：选择器改成 `.row.root > .coll-name`（高一档）→ 15px；行高 26 → 30px 托住字号；**活动根**再升一档到 16px，并加浅底 + 左侧强调条，让「当前操作的是哪个集合」一眼可见。验证：`tree-guides.spec.ts` 断言根行接出线/深度 0 列与根行图标圆心同列（≤1px）、接出线只到行中线且收起后不画、非活动根字号 > 树内条目、点一下变活动根后字号再变大。

- [x] **启动恢复上限硬编码 8、超出的目录静默丢弃**（功能）：`restoreRoots()` 直接 `savedRootDirs().slice(0, 8)`，第 9 个之后的目录既不提示也没入口，用户只能重新去系统对话框里翻。改法：上限进设置（`restoreLimit`，默认 8、范围 1–32，`internal/config` 与前端 `Settings` 两侧同步 + `Normalize` 夹住），截断时明确提示「已恢复 N 个，另有 M 个未恢复」；工具条加「最近打开」分组，一点即补开。
- [x] **「最近打开」不能用「当前打开的根」当数据源**（发现）：`client.dirs` 存的是**当前打开的根**（下次启动恢复用），而 `coll.open()` / `setActive()` / `closeRoot()` 都会 `saveDirs()` 覆盖它 —— 于是恢复被上限截断后，没恢复的目录会被立刻覆盖掉（「最近打开」永远是空的）；关掉某个根也会让它从列表里消失。改法：另存一份 MRU 列表 `client.recentDirs`（去重忽略大小写、最新在前、上限 20），打开目录时写入、关闭根**不**移除；「最近打开」= 该列表减去当前已打开的。
- [x] **启动时恢复与设置加载抢跑**（发现）：`onMounted` 里 `void settings.load()` 与 `void restoreRoots()` 并发执行，恢复上限从设置读，抢跑时会拿到默认值 8 —— 用户设的上限（比如 2）在某些启动时序下不生效。改法：`settings.load()` 的结果传给恢复（`settingsReady.then(() => restoreRoots())`）。

- [x] **MCP 的「默认工作目录」是进程级单例**（多客户端互相踩）：`use_workspace` 的选择存在 `Service` 里，而 HTTP 传输下一个进程会同时服务多个客户端（各自一个 `Mcp-Session-Id`）—— A 选定后 B 的「省略 project」会落到 A 的目录。而且这些工具的 `project` 在 schema 里还是**必填**（SDK 直接按 schema 拒掉缺字段的调用），所以「选定后可省略 project」实际只有显式传空串才生效。改法：选择状态从 `Service` 挪到工具层、**按会话 id 保存**（`req.Session.ID()`；stdio/内嵌只有一个会话，拿不到标识时用空串兜底 = 进程里那一份），`Service` 只按显式 `project` 解析、保持无状态；同时把 13 个入参的 `project` 从必填改为可选（`project,omitempty` + 说明「省略 = 本会话 use_workspace 选定的默认工作目录」），两份 MCP 文档的表格同步（`project` → `project?`）。验证：`session_test.go` 起真实 HTTP 服务、连**三个客户端会话**，断言各选各的、没选过的会话不继承别人的默认目标、显式 `project` 仍优先且不改默认。
- [x] **mcp 包测试会写进用户真实配置目录**（发现）：这些用例真的打开集合（写 `index/<uid>.sqlite`、必要时建默认环境），而包内没有配置目录隔离 —— 跑一次 `go test ./internal/mcp` 就在 `%AppData%\api-doc-client` 里留下几个索引文件。改法：加 `TestMain` 把配置目录指到临时目录（用两端都生效的 `API_DOC_CONFIG_DIR`）。

- [x] **一个进程只能开一个集合目录**（功能）：`App` 只有一个 `coll` 槽位，`OpenCollection` 是「替换」语义。改法：`App.colls`（**按规范化绝对路径为键**）+ `activeRoot`；`OpenCollection` 改为幂等追加（同目录重复打开只切活动根）；新增 `ListCollections`/`ActiveCollection`/`SetActiveCollection`/`CloseCollection`/`ReloadCollectionOf`。**关键取舍**：集合级方法签名一个没动 —— `requireCollection()` 改成从表里解析活动根，于是 60+ 方法与 `frontend/wailsjs` 生成绑定、devserver 反射桥的「参数个数精确匹配」都不用碰；需要指定非活动根的动作才走带 root 的新方法。
- [x] **集合身份用 uid 会串台**（发现）：两个工作目录完全可能是同一份集合的拷贝（清单 uid 相同、路径不同 —— e2e 夹具每次拷贝种子就是这种情况）：用 uid 当表键会互相覆盖（`collOrder` 出现重复 → `CloseCollection` 报「未打开」），索引也会落到同一个 `index/<uid>.sqlite` 互相污染。改法：根的身份 = 规范化绝对路径（Windows 忽略大小写）；uid 撞车时给后打开的根换区分索引键（`SetIndexKey`）并重建；历史条目记 root 而不是 uid。
- [x] **切根必须换一组标签**（发现）：标签按根分组（`client.tabs.<root>`），但「点别根里的请求」这条路径只切了后端活动根，没换标签组 —— 两个根的标签混在一起。改法：`tabs.switchRoot(root)` 收敛「落盘当前根 → 切活动根 → 恢复目标根会话」，点根行 / 点请求 / 工具条菜单都走它。会话/草稿键从集合 uid 改成 root，并保留旧键迁移（升级不丢现场）。
- [x] **跨工作目录移动请求**（功能）：目标侧重建 + 源进 `.trash`（uid/路径/序号由目标分配，避免两边出现同一个 uid）；两侧都校验只读镜像（mirror）拒绝写。目标创建失败 = 源未改动；源删除失败会明说「副本已建，源没删掉」。
- [x] **MCP 的「项目根」由调用方给 = 越权** 🔴：`-root` / `create_project(root=任意路径)`（还能临时建 registry）意味着调用方决定「能写哪里」；内嵌服务更是直接拿「当前集合的父目录」当根 = 隐式授权一整棵目录树。改法：`mcp.Config.Allow`（逐条**只读/可写**）成为唯一授权来源：扫描/定位/建项目都只在白名单内；写工具走 `WriteApp`（只读授权直接拒）；新增 `list_workspaces` / `use_workspace`（选定默认工作目录后各工具可省略 `project`）；白名单为空 = 不授权任何目录（**内嵌服务不监听**，设置页给出提示）；`cmd/mcpserver` 增 `-allow` / `-allow-writable`（`-root` 保留为旧写法，等价可写授权）。路径比较做绝对路径 + 软链复核，拒绝 `..` 逃逸。
- [x] **跨工作目录移动分组**（功能补全）：分组要连同子分组与请求整棵搬，直接递归「边搬边建」一旦中途失败会留下半搬状态，所以按四步走 —— ① 预检（两端可写、源分组存在且不是集合根、目标分组存在、目标下无同名分组）不通过就一个字都不改；② 在目标侧镜像出整棵分组结构（只有目录 + folder.yml，最轻、可整撤销）；③ 逐个搬请求（每个请求自身是「先建后删」的原子动作，用 `destOf` 映射把源分组路径对准刚建出的目标目录，避免双方清理规则不同导致落到别的目录）；④ 自底向上删源分组（`DeleteFolder` 只收空分组）整棵进 `.trash`。第 ②/③ 步失败 → 把已搬的请求搬回原位 + 逆序删掉已建的目标目录（源保持可用；搬回去的请求会拿新 uid，界面里对应标签要重开，报错里写明）；第 ④ 步失败只残留源侧空目录，如实回报让用户手工清理。界面侧同时在**拖动中就拦下**目标重名（两个根都有 `account` 时，落点直接标非法并写明「目标下已有同名分组」），空分组也照样跟过去。验证：`cross_test.go`（整棵搬运 + 目标新 uid + 空分组 + `.trash` + 同名预检不动源）、`multi-root.spec.ts`（请求单搬、重名拦截、分组搬进目标子分组后结构/`.trash`/树归属全对）。
- [x] **启动恢复多个目录**（功能）：`client.dirs` / `client.activeDir` 取代单个 `client.lastDir`（旧键自动迁移）；恢复上限 8 个，单个失败只提示并跳过（不阻塞其它根）。`collection:changed` 事件带 `root`，前端只重载发生改动的那一根；`CloseCollection`/退出时释放索引句柄（否则 Windows 上目录删不掉）。

## 2026.10.6（集合树可读性 + 关闭页签询问保存）

- [x] **集合树连接线与展开图标错位** 🟡：连接线列落在「行的内容起点」，正好是父分组展开按钮的**左边缘**（图标居中在按钮中部）→ 竖线看着与 `▾` 错开约 8px。改法：连接线列整体右移半个按钮宽（`GUIDE_OFFSET` = 8），使竖线穿过展开图标的圆心；缩进 13 → 16 保证横线仍有 8px 长度；行内「新建子分组」输入行同步。验证：`tree-guides.spec.ts` 断言各列 x 与对应层级的图标圆心同列（≤1px），且缩进/命中不受装饰层影响。
- [x] **方法标签比请求名小一号、看着没对齐** 🟡：`MethodTag` 默认 10px（页签/请求栏那种紧凑场景够用），树上请求名是 12.5px —— 同样 `line-height: 26px` 下两者基线差 1.25px，观感是两个字错位。改法：树内统一 12.5px（`Sidebar.vue` 的 `.row > .mt`）。验证：用例断言两者 `font-size` 相同、字面底边差 ≤1px，且仍在行内居中。
- [x] **关闭有未保存改动的请求会静默写盘** 🟡：`requestClose` 对非草稿直接 `close()`，而 `close()` 无条件 `flush()` —— 用户按 × 只想去掉页签，改动却被写进文件，也没机会选择丢弃。改法：`tabs.close(key, { save })` 增加「不写盘」分支（`closeDiscard`），关闭前弹「保存并关闭 / 不保存 / 取消」；保存失败（冲突 / 只读 / 磁盘错误）保留页签，原因由 `flush` 照常提示。顺带修两处同类问题：① 删除请求后关页签会把刚删掉的文件写回来 → 改走 `save: false`；② 丢弃草稿后不刷新 localStorage，重启会把已丢弃的草稿找回来 → `close()` 补 `saveDrafts()`。
- [x] **批量关闭也要逐个问**：关闭左侧 / 右侧 / 全部原先直接 `closeMany`（脏页签静默 flush 落盘、草稿跳过），与「单个关闭先问保存」不一致。改法：按**页签顺序依次**询问（对话框显示「批量关闭：第 i/n 个」），点「取消」= 中止整批、其余保留；草稿仍跳过（不静默丢未落盘内容）；顺序编排放界面层，store 只留 `close(key, { save })` 原语（删掉 `closeMany`）。验证：`regression-autosave.spec.ts` 覆盖「依次问两个」「取消中止」「一个保存并关闭 + 一个不保存」。
- [x] **没编辑也会出现「未保存圆点」** 🔴：`RequestEditor` 里「URL 变更 → 回填参数表 + 标脏」的 watch 取值是「当前 tab 的 url」，**切页签 / 打开另一个请求时 props.tab 一变它就触发**（实测：打开第二个请求凭空脏 1 个，右键切页签再脏 1 个）。旧实现把脏页签静默 flush 掉，所以一直没暴露；加上关闭询问后就变成「什么都没改也被问一次」。改法：watch 记住每个页签上次的 URL，只有该页签的 URL 真的变了才 `touch()`（切页签只重建参数表）。验证：用例断言打开/切换页签无圆点、真实编辑才有圆点。


## 2026.10.5（e2e 套件补全：从「跑不起来」到 49 条全绿）

- [x] **e2e 套件整体不可运行**：`frontend/e2e/` 有 11 个 spec 与完整 helpers，但 `cmd/testfixtures`（helpers 依赖的夹具服务）**不存在**，`package.json` 没有 `test:e2e` 脚本、没装 `@playwright/test`，也没有 `playwright.config.ts`，`check.sh` 没有 `--smoke/--full` 模式（README 描述的入口全部缺失）。改法：① 实现 `cmd/testfixtures`（状态码/重定向/延迟/大 JSON/二进制/gzip/非 UTF-8/Cookie/认证/multipart 等端点，附 Go 契约测试纳入门禁）；② 补 `playwright.config.ts`（按运行时间分产物目录、headed 自动 slowMo=300）与 npm 脚本；③ `check.sh` 增 `--smoke / --full / --e2e-ui / --skip-build`；④ 同步 e2e README 与 AGENTS.md。
- [x] **夹具的配置目录隔离在 Windows 失效 → 测试写进了用户真实配置目录** 🔴：helpers 只设 `XDG_CONFIG_HOME`，而 `os.UserConfigDir()` 在 Windows 只认 `%AppData%`（Node 传 env 时与继承的 `APPDATA` 大小写冲突更不可控）→ 实测 `%AppData%\api-doc-client` 下 `config.json`（含 token）/`cookies.json`/`history.jsonl`/`index/` 全被 e2e 改过。改法：新增 `config.EnvDirOverride`（`API_DOC_CONFIG_DIR`，两端都生效）作为唯一隔离开关，fixture 改用它，并补单测（这也是单测隔离问题的正解）。
- [x] **自写回环吞掉「保存后 400ms 内别人的改动」** 🟡：`watch` 的忽略窗口只按时间判定，`SaveRequest` 写盘后同一窗口里外部编辑器/`git` 的改动会被静默丢弃（干净页签不刷新、脏页签也不标冲突）——E26 用例正是这样复现的。改法：`watcher.IgnoreWrite(rel, hash, d)` 带内容指纹，窗口内只有「文件内容仍等于我方写入的那份」才忽略；`SaveRequest` 接上，其余调用点保持原语义。
