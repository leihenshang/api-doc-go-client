# 文档条目树化与页签同步实施方案（B19 / J11）

> **用途**：把「文档条目」从侧栏弹窗形态升级为**集合树叶子 + 独立页签**（与请求同构的草稿/脏点/保存模型），并补齐文档**删除**方向的同步闭环。按本方案分三阶段推进，每阶段独立可验证、可回滚。
> **关联**：功能清单 B9/B13/H1/J7（《客户端功能规划与完成情况.md》）、同步明细（《客户端与服务端同步实现现状.md》§二/§四）。
> **前提决定（已拍板，2026-10-16）**：不再考虑 Bruno 兼容性（I7 ⛔），因此文档树形态可自由设计，不受 `opencollection` 目录结构约束。

## 0. 现状勘察结论（2026-10-16 实测，方案立足点）

| 面 | 现状 | 结论 |
|---|---|---|

| share `Node` | `collection.Node.Type` 注释仅写 `folder \| request`（types.go L76），实际已流转 `"doc"` | 仅需注释修正，**无字段变更、不必为此发版**（随下次 share 变更带上） |
| 前端树渲染 | `Sidebar.vue` 行渲染/点击/重命名/删除/拖拽全部只认 `folder`/`request` 两支，`doc` 节点被**静默丢弃** | 主要工作量 |
| 扫描白名单 | `scanExtAllowed`（collection.go L943）：`.md` 仅当 `dir == docs/` 才视为文档 | 同级化必改：放开为任意目录 `.md`（排除 `README.md`） |

| doc 同步·服务端 | doc 类型六处全支持：`ext_uid`/`change_log`/`applyUpsert`/`applyDelete`/`apiSyncPayload 回显`/快照；Web 文档站（`DocListView/DocDetailView/ShareView`）原生展示 Markdown | **服务端与 Web 无需改动**，只做验收 |
| doc 同步·客户端 | push：`collectDocOps` 按 `Bind.DocHashes` 脏过滤**只发 upsert**；pull：`applyDoc` 落盘 upsert；`applyDelete` **无 doc 分支**；删除的本地 tombstone 检测**缺失** | 两个缺口 = J11 |
| 弹窗入口 | `DocsDialog.vue`（侧栏「⋯ → 文档」）为 B9 过渡形态 | 树化后**下线**，避免双入口漂移 |

## 1. 目标形态（已按用户确认收敛，2026-10-16）

- **文档与请求完全同级、无隶属关系**：`.md` 文档叶子可以出现在任意分组目录内，与 `.yml` 请求文件同目录混排；**支持拖拽**（文档拖入/拖出分组，与请求拖拽同一套 `useTreeDnd`/`canDrop` 机制）。
- 存量兼容：`docs/` 目录保留为**默认新建位置**（根级）；旧集合的 `docs/*.md` 继续按现有路径识别、挂在根，不受迁移影响。
- 点击文档叶子 → 顶部页签区打开**文档页签**：`DocEditor`（编辑/分栏/预览）承载，具备与请求一致的：脏点、手动/自动保存（`ExpectHash` 冲突检测）、关闭确认、重启恢复、撤销/重做、mirror 只读。
- 树与页签**按根归属**：文档属于所在根的本层目录；切根换页签组（现状机制）。
- 删除：行 hover 删除走 `App.DeleteDoc`（进 `.trash/`，B5 语义）；新增/修改/删除三类变更都经同步传播到服务端（J11，含**目录归属=服务端分组**的同步）。

## 2. 阶段一：文件层同级化 + 树化展示 + 文档页签（B19）

### 2.0 文件层（新增，一切的前置依赖）
- `collection.scanExtAllowed`：`.md` 由「仅 `docs/`」放开为**任意目录**；排除约定名 `README.md`（防误收，假设见 §6）。
- 树装配（collection.go 约 L1041）：doc 叶子由「强制挂根」改为**按 `Dir(Path)` 挂载**（`ensureDir(dir)`，与请求同路径语义）；同层排序 folder 在前，request/doc 按 `seq`（frontmatter 可选键，`docFront.Extra` round-trip 已保全）再名称。
- `CreateDoc(name, uid)` → `CreateDoc(name, uid, folder)`（空 folder = `docs/` 默认位；非空 = `<groupdir>/<sanitize(name)>.md`）；新增 `MoveDoc(uid, destFolder)`（仿 `MoveRequest`：`resolveFolderForMove` 拒后代 + 改 Path + `os.Rename`，uid/文件名主干不变）与 `RenameDoc(uid, name)`（只改 frontmatter `name`，与 B7 分组语义一致，文件改名留待后续）。
- 门面/IPC：`App.MoveDoc/RenameDoc` 新薄门面，`App.CreateDoc` 加 folder 参（缺省空串，旧调用不破）；`lib/ipc.ts` 同步。
- 分组菜单：目录行悬停「＋」菜单加「新建文档」（对齐新建请求入口）。

### 2.1 数据与类型（依赖 2.0）
- `frontend/src/types.ts`：`TreeNodeType = 'folder' | 'request' | 'doc'`；新增 `DocTabDraft`（见 2.2）。
- `frontend/src/lib/collTree.ts`：
  - `filterTree`：doc 叶子按名称参与即时过滤（文档不进 SQLite 索引——**范围裁剪保留**：索引型检索/URL 检索不覆盖文档）。
  - `canDrop`：**doc 与 request 同权**——可拖入 folder/根、可落在同目录任意位置；folder 可包含 doc；沿用拒移入后代规则（`MoveDoc` 层同样兼住）。
- Go 树已按 §2.0 输出同层节点；share `Node.Type` 注释补 `doc`（随下次必要发版，不单独发）。

### 2.2 页签模型（依赖 2.1）
`stores/tabs.ts` 以最小侵入扩展：
- `Tab` 增加判别字段：
  ```ts
  kind: 'request' | 'doc'          // 缺省（旧持久化 JSON 无此字段）按 'request' 处理
  doc?: { uid: string; path: string; name: string; content: string; icon: string }
  ```
  `request` 字段对 doc 页签置 `null`（类型放宽为 `RequestDoc | null`，消费点用 `kind` 守卫——逐个排查 `Tab.request` 的读取方：TabBar 徽标、RequestEditor 挂载、send、H7 快照）。
- 新动作：
  - `openDocTab(root, uid)`：`api.readDoc(uid)` → 建 doc 页签（`dirty=false`）；同 uid 已开则聚焦（与 openRequest 同逻辑）。
  - `saveDoc(tab)`：手动保存与自动保存防抖走同一入口——`api.saveDoc({uid,name,path,content,icon})` + `ExpectHash`（`App` 侧新增薄门面 `SaveDocExpectHash(doc, expectHash)`：比较 `Collection.FileHashOf(path)`，冲突返回 `[conflict]` 标记，复用 H8 冲突条 UI 与「重载/另存」动作）。
  - 监听回填（H9）：watch 事件里 `docs/*.md` 变化 → 干净页签回填 content、脏页签标冲突（`collection:changed` 已带 path，加 doc 分支）。
- 持久化：`client.tabs.<root>` 序列化含 `kind/doc`；`client.drafts.<root>` 对 doc 页签存 `{name,content}` 草稿。旧数据无 `kind` 字段 → 反序列化补默认，**向后兼容、无迁移**。
- 撤销/重做（H7）：快照单元从「请求文档」泛化为「请求或 doc 内容」二选一（快照栈沿用，仅形状判别）。
- 显隐：doc 页签时右侧响应面板整体隐藏（`v-if="tab.kind==='request'"`），编辑区满幅；发送/取消/代码生成等入口同样隐藏；mirror（J7）禁用编辑沿用 `isReadOnly`。

### 2.3 树交互接线（依赖 2.0/2.1/2.2）
- `Sidebar.vue`：行渲染新增 doc 支（图标 `DocumentTextOutline` + 名称 + hover 重命名/删除，操作组与 request 行同构，调用换为 `coll.renameDoc/deleteDoc`）；点击 → `tabs.openDocTab`；H11 联动：`openDocTab` 后树滚动定位（按 path）。
- **拖拽**：`useTreeDnd` 的 drop 处理加分支 `node.type==='doc' → coll.moveDoc(uid, destPath)`（与 moveRequest 并列）；拖动视觉复用现有高亮（drop-ok/drop-bad）。
- `DocsDialog` 下线：移除「⋯ → 文档」菜单项与 `DocsDialog.vue`（`DocEditor.vue` 保留，作为页签内容组件复用；其头部保存/关闭按钮并入页签工具带）。
- `App.vue`：主区渲染 `tab.kind==='doc' ? DocEditor : RequestEditor`；快捷键 Ctrl+S 分派到 `saveDoc`。

### 2.4 阶段一验证
- 文件层 Go 单测：任意目录 `.md` 被识别为 doc、`README.md` 不被识别；`MoveDoc` 改路径+uid 不变+拒后代；`CreateDoc(name, folder)` 落组目录；树装配 doc 按目录挂载与混排。
- `bash scripts/check.sh`（类型/构建/i18n）。
- e2e（重建 dist 后跑）：`docs-ui.spec.ts` 改写为树形态用例——①根级与组内各建一篇文档，树同层出现 doc 叶子②点叶子开页签（`doc.save` 可见）、编辑脏点、Ctrl+S 落盘（poll 文件内容）③**拖动文档入分组**（poll 文件路径变化、uid 不变）④关闭脏页签询问⑤双根场景：根 A 有文档、根 B 无——切根页签组与叶子同步变化。
- 手工钩子齐全：`tree.docRow`、`tab.docDirty`、`doc.save`（已有）。

## 3. 阶段二：文档同步闭环（J11：删除 + 目录归属，仅 engine 改动，服务端零改动）

- **push 归属**：`collectDocOps` 的 payload 补 `GroupUID`（= `d.Path` 父目录对应的 folder uid，根级/`docs/` 下为空串→服务端未分组）；服务端 applyUpsert 已支持（§0）。**拖动改路径的后果**：文件 hash 按新路径重算→产生一次全量 upsert（带新 group_uid），幂等、无 delete，可接受（方案文在 §5 风险表备注）。
- **pull 归属**：`applyDoc` 新建分支按 `p.GroupUID` 用 `findDirByUID` 定目录（同 api 拉取路径语义，engine.go L449 同款）；组本地不存在时先建组后落位（沿用 typeRank 的 group→doc 拓扑序，已保证）。
- **push 删除**：`collectDocOps` 增加 tombstone——`Bind.DocHashes` 有记录但 `ListDocs` 已无该 uid → `Op{delete,doc}`（照抄 `collectExampleOps` 模式）；`applyPushed` doc 分支删除成功后清 `DocHashes`。
- **pull 删除**：`applyDelete` 增加 `case "doc": _ = e.Coll.DeleteDoc(it.UID); delete(e.Bind.DocHashes, it.UID)`（进 `.trash`）。
- **服务端**：仅验不写：补集成断言单测 `TestSyncDocGroupPlacement`（带/不带 group_uid 两种 upsert → group_id 与 parent_missing）；删除链路已有 `TestSyncVariableRoundTrip` 同款机位，顺手加 doc 一例。
- 验证：客户端 engine 单测（group_uid 双向 + tombstone 两向）+ 服务端 `GOWORK=off go test ./internal/service/`。

## 5. 风险与回滚

| 风险 | 缓解 | 回滚 |
|---|---|---|
| 扫描白名单放开（任意 `.md` 入树）改变既有集合观感（如外部塞入的笔记 md 被当文档） | 排除 `README.md`；白名单改动单列一个提交，`scanExtAllowed` 集中一处易收紧 | 还原该提交即回到「仅 docs/」；文件不会被删，仅识别行为变化 |
| 拖动后重推整篇 doc（hash 换路径变）产生冗余 upsert | 服务端 upsert 按 ext_uid 幂等覆盖，仅多一条 change_log | 无需处理；若噪可后续按 (uid,content) 去重 |
| `Tab` 类型放宽引发请求路径回归 | 所有 `request!` 读取点用 `kind` 守卫 + 阶段一 e2e 全量跑（83 条基线） | 阶段一为独立提交序列，`git revert` 即回到弹窗形态（DocsDialog 在阶段三才删除，天然保留回退面） |
| 旧 localStorage 页签数据无 `kind` | 反序列化默认 `'request'`，无迁移脚本 | 兼容读取即可，无需回滚数据 |
| doc 删除同步误删本地文件 | 走 `.trash`（可恢复）；tombstone 仅对「推送记录在册」的 uid 生效 | 阶段二独立提交；服务端侧删除本就有冲突副本机制 |
| 文档误拖进非法位置（如另一文档下——文档无子级） | `canDrop` 目标只允许 folder/根；`MoveDoc` 层再校验 | 行为收缩在前端 lib 层，随时可收紧 |

## 6. 实施顺序与提交断点约定

1. 每阶段内部按「类型/lib → store → 组件 → i18n（双语 key 同步）→ e2e」小步提交，均过 `check.sh` 后落断点。
2. 阶段一、二可并行开发但**分别提交、分别验证**；阶段三收尾文档最后动。
3. 关键假设（已按用户确认更新 2026-10-16）：**同级、可拖、同目录混排已定**；仍保留的收缩：文档不进索引搜索（正文/URL 检索另立项）、`README.md` 不视为文档条目、重命名只改 frontmatter 不改文件名、DocsDialog 下线以树为唯一入口。
